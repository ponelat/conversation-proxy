conversation-proxy

An observable proxy between an application and an LLM provider. It owns conversation persistence, composes context intentionally from a generic hierarchy, and records the exact context sent to the model so it can be polled live, replayed, and evaluated.

Node.js · TypeScript Hono HTTP standalone or embedded Postgres / in-memory v1 · text-only core Apache-2.0
Overview Pipeline Layers Deployment Debug plane HTTP API Decisions Deferred

01What it is

One front door — send() — backed by a handful of swappable interfaces. Each layer changes for a different reason and is wired together by constructor injection; the HTTP layer is just an adapter over the facade, so the same core runs standalone or embedded in a Next.js server.

Intentional context

An assembler composes the prompt from ordered, stability-tagged segments — domain-aware but vendor-agnostic.

Generic hierarchy

A conversation is addressed by a /-joined scope ("user_42/client_88") — the scope is the id. Same scope → same thread. The server attaches no meaning to any segment.

Observable by default

Every call writes a CallRecord envelope and emits lifecycle events to a pollable debug log.

02The send pipeline

One path serves every agent. Persistence is a hook, not a mode — a persist:false utility agent runs the identical flow with steps 1 and 5 turned into no-ops.

03The layers

Independent interfaces, each with a single reason to change. The litmus test: “if I change how the patient record is cached, does the storage layer change?” — the answer must be no.

ConversationStore store/*.ts

Scope-addressed conversations + messages. InMemoryStore and PostgresStore behind one interface; same test suite both backends.

Assembler assembler/*.ts

An agent hook that composes AssembledContext — ordered segments tagged static/semi-static/volatile. Default = history + current turn.

CacheStrategy cache/*.ts

Reads stability tags, flattens to the wire shape. PassthroughCache in v1; usage.cachedTokens recorded from day one.

LLMProxy proxy/proxy.ts

ObservableLLMProxy wraps a Provider: emits events, captures latency + usage, writes the CallRecord — even on failure.

Provider provider/*.ts

The only vendor-aware piece. OpenAIProvider (Chat Completions) and a deterministic FakeProvider.

Facade facade/agent.ts

PersistedConversationAgent.send() orchestrates the five steps and propagates one traceId. No oneshot branch.

DebugEventLog debug/*.ts

Pollable lifecycle events with a monotonic cursor. In-memory ring buffer or Postgres debug_events, by backend.

ContextExplorer debug/explorer.ts

Read-only: actual context for a traceId, a no-LLM preview, and storage browse by scope prefix.

Agent registry agent/*.ts

Agents are manifests (programmatic or *.agent.ts files). Missing hooks fall back to defaults; all-or-nothing boot.

CallRecordStore telemetry/*.ts

The full per-call envelope — the future eval dataset. In-memory or Postgres call_records.

04Two ways to run it

The whole service is one Hono app, so app.fetch is exactly what a Next.js Route Handler wants.

Standalone

A long-lived Node process via @hono/node-server.

# dev (tsx) or built bin
npm run serve
node dist/main.js serve

Embedded (Next.js)

Mount app.fetch; register agents programmatically.

import { createServer, loadConfig } from "conversation-proxy";
const ready = createServer(loadConfig(), {
  agents: { vet }, scanDir: false,
});
export async function POST(req) {
  return (await ready).fetch(req);
}

Backends swap by config. CP_STORE = memory | postgres · CP_PROVIDER = fake | openai. For serverless / multi-instance, use Postgres so the store, records, and debug log are shared across instances.

05Debug plane — cursor polling

No long-lived connection. Clients poll /debug/events with the last cursor to get deltas — works behind load balancers and serverless. Gated by a separate token and off unless CP_DEBUG_ENABLED.

// 1. probe the head, then tail deltas
GET /debug/events                 → {events:[], cursor: 42}
GET /debug/events?after=42        → {events:[…], cursor: 47}
GET /debug/events?after=47&traceId=tr_…

// response
{ events: DebugEvent[], cursor: number, dropped: boolean }

Lifecycle events

  • request.received
  • context.assembled — segments + tokens
  • cache.prepared — breakpoints
  • llm.request — exact messages + system prompt
  • llm.response — reply + usage + latency
  • error — stage + message
  • llm.chunk defined, not emitted

06HTTP API

Two planes, authenticated separately (CP_API_KEY for control, CP_DEBUG_TOKEN for debug). Documented in openapi.yaml; a CI test asserts the routes never drift from the spec.

MethodPathPlanePurpose
GET/healthopenliveness
GET/agentscontrollist loaded agents
POST/agents/:agent/messagescontrolthe send() front door
GET/agents/:agent/contextcontrolpreview context (no LLM)
GET/conversations?scope=…controlfetch the conversation + messages for a scope
GET/records/:traceIdcontrolone call envelope
GET/records?agent=&scopePrefix=…controlquery envelopes
GET/debug/events?after=…debugpoll event deltas
GET/debug/context/:traceIddebugexact context sent
POST/debug/previewdebugassemble preview
GET/debug/explore?scope=…debugbrowse storage + records

No explicit conversation creation. A conversation comes into being by being talked to (POST /agents/:agent/messages); the scope is the id, so there is no separate create call and no handle to thread — reuse the scope to continue, append a /<uuid> segment to branch.

07Key decisions

The firm architectural decisions (D1–D17) live in the spec; these are the load-bearing ones, plus the three reversed during the build.

Three separable layers

Store · Assembler · CacheStrategy, plus the Proxy. Each changes for a different reason. D1

Scope is the conversation id reversed D2

A /-joined string of opaque segments IS the id — one scope, one thread. Boundary-aware prefix lookup; branch with a /<uuid> segment. D2

Persistence is a hook, not a mode

“One-shot” = persist:false. One front door, one observability path. D15

Caching starts as passthrough

Correctness first; usage recorded so prefix caching can be justified by data later. D4

Node, not Deno reversed D7

To embed in a Node/Next.js server. Hono made the HTTP layer port cleanly.

Embeddable + standalone reversed D6

One Hono app; createServer() returns app.fetch to mount anywhere.

Debug = polling, not SSE changed

Cursor pagination over /debug/events — serverless-friendly, durable via Postgres.

In-repo migration runner reversed

Inlined ordered migrations, own ledger in a dedicated schema, advisory-locked. Rewrite-in-place vs forward-only governed by a high-water mark. D12 · MIGRATIONS.md

08Deferred (designed, not built)

v1 is a lean text-only core. These are understood and additive — see docs/NOT_DONE.md for the full inventory and caveats.

Blobs / multimodal

BlobStore + media resolver; content is text-only today. D16, D17

Extra-context store

Scope-keyed derived domain data the assembler reads. D14

Prefix caching

PrefixCache with breakpoints, once usage justifies it. D4

SDK + types package

The CLI client is the seed; a published SDK is later. D13

Web observation UI

Live view, inspector, explorer — consumes the wired debug plane.

Client-facing streaming

Token streaming + llm.chunk to the caller. Q4

Multi-step agent loop

Tool-calling loop inside send() — no interface change needed.

Multi-provider routing

One provider per process today; Anthropic + fallback later. Q5

Debug-event retention

The Postgres event log has no pruning/TTL yet. D10
