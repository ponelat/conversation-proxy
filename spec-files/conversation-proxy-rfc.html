00

What this is, and why it's shaped this way

LLMs are stateless: every call must carry the full context. A “session” is therefore something this service maintains, not something the model holds. The whole design follows from one move — splitting that responsibility into parts that each change for a different reason, then exposing them behind a single front door.

The problem

Context is the product

What gets sent to the model — the system prompt, the patient record, the conversation so far — is the lever for both quality and cost. It must be deliberate, inspectable, and replayable.

The shape

Three layers + a proxy

A store (persistence), an assembler (composition), a cache strategy (vendor mechanics), and a proxy (the model call + telemetry). Independent, swappable, individually testable.

The front door

One agent interface

The app calls ConversationAgent.send(). Even as a one-shot, it is a real agent: persistent state, a managed context window, a controlled model interface.

DomainThe first consumer is a veterinary application with the hierarchy user → client → patient → conversation. But the server stores scope as a generic ordered array — ["user_42","client_88","patient_3","2026-W26"] — and attaches no meaning to any level. Another consumer could use ["org","team","thread"]. New levels are just longer arrays.
01

Decision register

Every firm choice, recorded with its rationale so it isn't accidentally relitigated. Tap any row to read why. These are the heart of the RFC — if you disagree with one, this is the place to say so.

D1

Three separable layers, not one firm▸

Store, Assembler, CacheStrategy and the Proxy are independent interfaces wired together — never merged. Each changes for a different reason. The litmus test used throughout: “if I change how the patient record is cached, does the storage layer change?” The answer must be no.

D2

Identity is a generic hierarchy array firm▸

Retrieval is listConversations(scope) where scope is an ordered array of opaque string IDs — broadest first, leaf last, e.g. ["user_42","client_88","patient_3","2026-W26"]. The server attaches no meaning to any level; the vet domain is just one mapping. New levels are simply longer arrays, and the order is what enables prefix-based extra-context lookup.

D3

The Assembler is a distinct third role firm▸

Context is composed from multiple sources, ordered most-stable-first. The assembler knows the domain but is vendor-agnostic; the cache strategy knows the vendor but is domain-agnostic. They communicate only through stability tags.

D4

Caching starts as a no-op, data-driven firm▸

The default cache strategy is passthrough: send everything, ignore caching. cachedTokens is recorded anyway, so the team accumulates the data to decide when prefix caching is worth enabling. Correctness first.

D5

A facade exposes a single interface firm▸

The application talks to one object, ConversationAgent.send(). It only orchestrates; heavy logic is tested at the layer below, so its own test is small.

D6

Dedicated service, not embedded import firm▸

The realtime debug channel needs a long-lived process that holds streaming connections. Serverless request handlers cannot be that. The layers become the internals of this service.

D7

Deno (TypeScript), not Go firm▸

The workload is I/O-bound, so Go's CPU/concurrency edge isn't perceptible. Deno gives native TS with no build step, runtime dynamic import() for the optional hook, and permission flags that bound the process. Revisit Go only on a profiled bottleneck.

D8

REST + SSE, not gRPC firm▸

The debug consumer is a browser tool. gRPC streaming into a browser needs grpc-web + a proxy. REST + SSE is far simpler for “a tool taps in and watches events flow.”

D9

Two planes in one service firm▸

A control/data plane (REST) and a debug plane (streaming + explorer). The debug plane can be auth-gated, disabled in prod, and scaled independently so a slow observer never backpressures a real request.

D10

Proxy emits events; channel is a subscriber firm▸

The proxy depends on a DebugChannel interface and calls emit(). It knows nothing about SSE/WebSocket. Default is NullDebugChannel — zero overhead, no observers.

D11

Assembler is a single optional drop-in hook firm▸

One file at ./assembler/hook.ts exporting assemble. Loaded by dynamic import at startup. Absent → default, server boots normally. Present but broken → fail loudly, never a silent downgrade.

D12

Owns its tables; tracks its own migrations firm▸

Tables live in a dedicated Postgres schema; migration state is tracked in the service's own ledger via a standard tool, isolated from other migration systems on a shared DB. Default migrate command; --migrate-on-startup runs under an advisory lock.

D13

Two machine-readable API contracts firm▸

OpenAPI 3.1 for the synchronous control plane, AsyncAPI 3.0 for the event-driven debug plane. The SDK generates from / validates against both, so server and client cannot drift.

D14

Scope-keyed extra-context store firm▸

A separate KV store keyed by scope holds arbitrary JSON: getExtraContext / setExtraContext / clearExtraContext. Client code writes it out of band; the assembler reads it to pull derived domain data (e.g. a patient's last SOAP note) into context. Exact-match is the primitive; an opt-in prefix walk inherits from ancestor levels. The server never interprets the JSON.

D15

One unified agent model; persistence is a hook firm▸

There is one kind of agent, defined by a single <name>.agent.ts manifest (async factory). No conversational-vs-oneshot mode. An agent's persist field is a function (custom), false (utility: no messages stored), or true/undefined (default). A summarizer or transcriber is simply persist:false — it reads no history and writes nothing, but its observability is identical. One front door (send), one CallRecord shape, no branching.

D16

Normalized content; pristine persisted vs. enveloped assembled firm▸

Message content is a normalized array of parts (text/image/audio/file); non-text parts are blob-only via sourceUri — never inline base64 at rest. The persisted ContentPart/StoredMessage never carry transport metadata. The ephemeral AssembledPart/AssembledMessage wrap the pristine part by value and add a meta channel; the assembler sets meta.resolve to tell the resolver which parts to hydrate to bytes. Default: current-turn media as bytes, history as refs. resolve:true parts must live in a volatile segment.

D17

Blob store with write-behind mint firm▸

Media lives in an S3-compatible blob store. mint() returns a UUID/ref synchronously and uploads in the background, with bytes also held in an in-process pending buffer. The resolver hydrates from the buffer first, so the LLM call never waits on S3 persistence. Stored messages and CallRecords keep only the ref; the debug UI resolves refs to fetchable URLs, never inline bytes.

04

Agents: one file, one manifest, persistence as a hook

An agent is a single file — <name>.agent.ts — whose async factory returns a manifest of optional hooks (assemble, cache, persist). The filename is its identity; the server discovers all agents by directory scan at startup. There is one kind of agent: a "one-shot" utility (summarizer, transcriber) is just persist: false — no stored messages, but identical observability.

Segment order · most-stable first

The assembler tags each segment with a stability class. The cache strategy reads those tags to place breakpoints later — the two never reference each other directly.

static  system / clinic prompt — shared across everyone
semi-static  client profile — shared across this client's pets
semi-static  patient record — shared across this pet's conversations
volatile  this conversation — changes every turn
Caching depends on itFor an upper segment to hit cache across conversations, its serialized form must be byte-identical every time. The assembler owns deterministic normalization — sorted keys, fixed formatting, no timestamps.
Extra-context · D14Derived domain data (a patient's last SOAP note, allergies, a rolling summary) is written by client code to a scope-keyed store and read by the assembler. Set at the patient level, it naturally lands in the semi-static prefix region. See the Extra-context tab above.
Media · D16 / D17Content is normalized parts (text/image/audio/file); media is blob-only (a sourceUri), never base64 at rest. The persisted part stays pristine; the assembler tags an assembled part with resolve: true to have the resolver hydrate it to bytes at the transport boundary. The message list always holds refs, so the cache prefix stays byte-stable. Blob upload is write-behind, so the LLM call never waits on persistence. See the Content and Blob tabs.

Default · zero config

Loader · absent → default, broken → loud

06

How a request actually flows

The primary path — one user turn to one reply — touching every layer once. Run the trace in the pipeline at the top of the page to watch it animate.

App calls send({ agent, scope, input }) through the SDK → POST /agents/:agent/messages. input is an array of content parts (text + media). Unknown agent → 404.
Store appends the incoming user turn. Proxy emits request.received.
Assembler hook reads scope-attached extra-context (e.g. the patient's last SOAP note) plus conversation history, normalizes the upper segments, returns stability-tagged segments. Emits context.assembled.
Cache strategy (passthrough) flattens to a single array, prefixTokens = 0. Emits cache.prepared.
Proxy calls the provider, emits llm.request then llm.response, and writes the full CallRecord envelope — the raw material for later evals.
Store appends the assistant reply. The app receives { reply, conversationId, traceId, usage }.
Preview · no LLMThe observation UI can call the same assembler hook without the proxy step (POST /debug/preview) to see exactly what context would be sent — and whether the prefix is byte-stable — before any real request goes out.
07

Build order

Each stage is independently testable and yields something runnable. The tightest first slice is stages 1–3.

Shared types package — every interface plus the assembler test kit. No logic.
InMemoryStore + tests — append/retrieve, scope queries. No LLM.
Default assembler + loader — assert all three paths: absent, valid custom, broken custom.
PassthroughCache — returns everything, prefix 0, no breakpoints.
LLMProxy with a fake provider + NullDebugChannel + CallRecordStore — assert envelope + emit sequence.
Facade — inject fakes; assert orchestration order and traceId propagation.
Migration runner + 001_init — dedicated schema, own ledger, coexists with unrelated migrations.
REST server + openapi.yaml — wire endpoints, load the hook, validate responses against the schema.
BroadcastDebugChannel + SSE + asyncapi.yaml + ContextExplorer — assert stream + unsubscribe on disconnect.
Real provider adapter (Anthropic / OpenAI) behind the proxy.
PostgresStore (Supabase) + 002_call_records — the whole suite passes unchanged against Postgres.
TypeScript SDK wrapping REST + SSE, re-exporting shared types.
Observation UI — live stream, context inspector, preview, storage explorer.
